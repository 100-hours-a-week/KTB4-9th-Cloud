# S1' 사전 측정: 채점 워커 중단 x core 풀 10/131

2026-11-24 KST. 보정 1회차 재현 실패 뒤 "지연 사건 촉발"(사용자 결정)이 실제로 어디까지 번지는지 재기 위해 정식 실행기 밖에서 두 번 쟀다. 부하 RATE 30, 15분, 시작 3분 뒤 채점 워커를 5분 멈췄다(채점 노드 cordon + 워커 파드 삭제). 스크립트는 세션 작업 공간의 `pilot-judge-down.sh`, `pilot-pool131.sh`(저장소 밖)다.

## 해석

- 풀 10에서는 기준선 1회차의 실제 회수와 같은 연쇄가 재현됐다. 제출 요청이 채점 대기 중 연결을 쥐어 core 풀이 바닥나고, 같은 풀을 쓰는 문제 조회·major-core가 연결 획득 제한(3초)에 걸려 5xx를 냈다
- 워커가 돌아온 직후(10:13) 밀린 작업이 풀리며 한 번 더 흔들렸다
- 풀 131에서는 제출 요청이 연결을 더 쥐어도(파드당 최대 41) 다른 경로가 쓸 연결이 남아 연쇄가 생기지 않았다. DB 연결 합은 160으로 RDS 상한에 한참 못 미쳤다
- 따라서 처음 설계의 "풀 확대 PR이 RDS를 고갈시킨다"는 이 부하에서 성립하지 않고, 실제 위험은 "풀이 작아 채점 장애 하나로 핵심 경로가 멈춘다"이다. S1'을 이 연쇄로 다시 설계했다(설계서 6.1)

## 측정의 한계

- 채점 노드를 cordon하자 클러스터 오토스케일러가 새 채점 노드를 띄웠다(10:09 생성). 워커가 새 노드에서 다시 떴을 수 있어 실제 중단 시간은 5분보다 짧았을 수 있다. 두 측정 모두 같은 방식이라 비교는 유효하지만, 정식 실험은 시간이 일정한 KEDA 일시 정지(`paused-replicas: 0`)로 바꿨다
- core HPA가 부하 중 3파드로 늘어난 구간이 있다(두 측정 모두)
- 각 1회 측정이다. 정식 개선 전 실험은 3회 반복한다
