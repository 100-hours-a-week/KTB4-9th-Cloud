# 역할 체크리스트

기업은 지휘, 기록, 전파를 다른 사람이 맡지만 이 환경은 한 사람이 세 장을 순서대로 수행한다(설계서 7.4). 각 항목 옆에 한 시각(KST, 초 단위)을 적는다. 이 시각이 실험 기록의 선언, 완화, 원인 파악 시간이 된다.

## 1. 지휘

| 순서 | 항목 | 시각 |
|---|---|---|
| 1 | 증상 알림 확인. 알림 이름과 묶음(`journey`) 기록 | |
| 2 | Discord에 `INC-<날짜>-<번호>` 스레드 열기(선언) | |
| 3 | `severity.md`로 등급 확정. 애매하면 높은 등급 | |
| 4 | 최근 24시간 변경 확인: Argo CD 배포 기록, 승격·값 변경 PR, Grafana 배포 주석 | |
| 5 | 완화 방법 결정: 롤백, 재시작, 확장, 격리, 재배치 중 하나 | |
| 6 | 완화 조치 완료 | |
| 7 | 원인 서비스와 구간 특정(메트릭, 로그, 트레이스 중 무엇으로 봤는지 함께) | |
| 8 | 복구 확인: 해당 SLO가 목표 안으로 돌아와 1분 유지 | |
| 9 | 종료 선언 | |

## 2. 기록

| 순서 | 항목 | 시각 |
|---|---|---|
| 1 | 스레드 첫 글: 탐지 시각, 알림 이름, 제안 등급 | |
| 2 | 판단할 때마다 한 줄: 무엇을 보고 무엇을 정했는지 | |
| 3 | 조치할 때마다 한 줄: 명령이나 PR 링크 | |
| 4 | 등급이 올라가면 이유와 함께 기록(내리지 않는다) | |
| 5 | 종료 후 실험 기록 md의 사람 칸 채우기 | |

## 3. 전파

| 순서 | 항목 | 시각 |
|---|---|---|
| 1 | 첫 공지(SEV1, SEV2는 즉시): 확인된 최소 정보만 | |
| 2 | 매 공지 형식: 상태 / 영향 받는 기능 / 다음 조치 / 다음 공지 시각 | |
| 3 | 완화 후 공지 | |
| 4 | 종료 공지와 포스트모템 예정일 | |
